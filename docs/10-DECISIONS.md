- **결과:** 구현 코드를 두지 않으며 최종 이전 뒤 read-only archive로 전환한다.

## D02 — 레인 모델

- **결정:** `P`와 `G`는 선형 spine, `L`은 트리거 기반 한정 작업 큐다.
- **결과:** L01~L15에 진입 조건·한 회차 범위·산출물·반복 여부를 부여한다.

## D03 — 42 정본

- **결정:** 작은·단일 개념 과제 8개는 `42` orphan branch, 독립 제품 6개는 standalone 저장소로 둔다.
- **결과:** 동일 코드 복제를 금지하고 `42/main`은 색인만 소유한다.

## D04 — Guides 정본

- **결정:** 가이드 17개는 모두 `guides` orphan branch로 통합한다.
- **결과:** 각 branch가 README·LICENSE·실습·검증·branch-local CI를 자체 소유한다.

## D05 — 첫 지원 시점

- **결과:** P15와 P17 이후 마일스톤은 복습용 병렬 PATH의 실제 완료 순서에 따라 지원 직군을 확장하고 코딩 테스트는 지원과 병행한다.

## D06 — 채용 공고

## D07 — 라이선스

## D09 — 복습용 4트랙 병렬 모드

- **결정:** 기본 PATH와 별도로 C·C++·WEB·SPORTSBOOK을 병렬 진행하고, 각 트랙 내부에는 필요한 가이드 구간과 프로젝트를 하나의 선형 순서로 교차 배치한다.
- **결과:** 프로젝트만 원자적으로 완료한다. 가이드 저장소 전체의 원자성은 해제하지만 필수 장·실습 범위는 제거하지 않고 PATH의 지정 위치에서 모두 이수한다.
- **SPORTSBOOK 시작:** `guide-java`와 P16은 현재 회차의 P15를 기다리지 않는다. 이 모드는 전체 과정을 이미 한 번 수료한 복습 실행안이므로, 현재 회차에 필요한 직접 선행 범위만 하드 동기화한다.
- **하드 동기화:** `guide-algorithms` 01~10 → P09, `guide-computer-networks` 01~11 → network 12, `guide-web-applications` 07~08 → P22, WEB 인프라·DB·network 12 → P24의 네 지점을 둔다.
- **가이드 분할:** algorithms 01~10은 P07 직후 먼저 완료해 P09를 개방하고, C++ generic·RB-tree는 그 뒤 P08에 붙인다. web applications 07~08은 P22를 개방하고 09는 P15 쪽에 남긴다. distributed services 01~07은 P20을 개방하고 08~10은 P24 직전에 완료한다.
- **P24 셸 범위:** P24가 다중 저장소 빌드·검사·release script를 직접 수정하므로 `guide-shell-scripting` 01~08은 이 실행 모드에서 조건이 충족된 필수 범위가 된다.
- **복귀:** 한 트랙에서 미완료 P를 두고 다음 G/P를 열거나 필수 가이드 범위가 누락되면 완료 근거를 보존한 채 기본 PATH로 돌아간다.

## D10 — P09 `stack-sort` 조기 배치

- **결정:** 복습용 C 트랙에서 P09를 마지막이 아니라 P03 직후로 옮긴다.
- **근거:** P09는 P01의 C 소유권, P02의 입력·descriptor 상태, P03의 parser·부분 출력 경험을 직접 재사용한다. signal IPC, shell process graph, pthread와 남은 Unix·OS 폐쇄 범위는 P09의 시작 조건이 아니다.
- **하드 게이트:** P09 시작 전 `guide-algorithms` 01~10 완료는 유지한다.
- **경계:** P 번호, 저장소 정본과 기본 PATH의 선형 순서는 바꾸지 않고 복습용 병렬 PATH의 실행 위치만 바꾼다.

## D11 — 병렬 완료와 지원 활성화

- **결정:** P14는 일반 지원의 공통 개방점으로 유지하되 P15와 P17 이후 증거 gate의 실제 완료 순서는 고정하지 않는다.
- **결과:** P14 전에 끝난 확장 마일스톤은 L14에서 함께 반영하고, P14 뒤에 끝난 마일스톤은 실제 완료 순서대로 L15를 한 번씩 연다.
- **금지:** 번호 순서를 맞추기 위해 완료 증거를 숨기거나 미완료 프로젝트를 완료한 것으로 계산하지 않는다.

## D12 — 하드 동기화 방향과 시각 표기

- **방향:** `A → B`는 B가 A의 완료를 기다리는 단방향 gate다. A는 B를 기다리지 않으며, A에 도착했거나 진행 중인 상태는 완료로 계산하지 않는다.
- **완료 조건:** A의 지정 본문·실습·검증과 P0/P1 처리가 끝나야 B를 시작할 수 있다. B는 A 외에도 자기 트랙의 내부 선행을 모두 충족해야 한다.
- **노드:** 별도의 동기화 전용 checkpoint 노드를 두지 않는다. 외부 선행은 실제 소비 블록의 진입 조건과 제공 블록에서 소비 블록으로 향하는 직접 간선으로 표현한다.
- **색상:** S1~S4 관계마다 별도 강조색을 사용하고, 같은 관계의 실제 제공 노드와 실제 소비 노드만 같은 색을 사용한다. 서로 다른 관계는 같은 색을 공유하지 않는다.
- **중복 참여:** 하나의 블록이 두 관계에 참여하면 두 색을 함께 표시한다. 현재 `WEB-G07`이 S2의 소비 노드이자 S4의 제공 노드다.
